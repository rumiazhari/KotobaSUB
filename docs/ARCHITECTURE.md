# Architecture

## Implemented foundation
`KotobaSUB.Core` owns immutable subtitle/token records, overlay preferences, validated local settings and rotating logs. `KotobaSUB.Windows` owns WPF layout, HWND styles, global hotkeys, tray lifetime and the small native settings window. `KotobaSUB.Tests` is an executable regression suite including real Japanese dependencies. UI-only rendering is behind `ISubtitleRenderer`; sample data is explicit developer/tray preview data, not an input provider.

Glyphs are drawn with a black outline beneath white fill so text remains legible over light and dark content. A down-only Viewbox prevents clipping in constrained geometry; wrapping is recalculated on resize. The WPF window has `AllowsTransparency`, a transparent background, no chrome, no taskbar item and `ShowActivated=false`. The native layer applies TOOLWINDOW, NOACTIVATE and TRANSPARENT while locked. WPF owns LAYERED. SetWindowPos uses HWND_TOPMOST and SWP_NOACTIVATE. Edit mode clears TRANSPARENT, supplies a temporary position-edit surface and allows drag/resize, then removes it on lock. It never adds decoration to normal subtitles. Hotkeys are registered against the overlay HWND and released on shutdown. Registration failure is visible in logs/tray; no keyboard hook is required.

Settings and logs live under `%LOCALAPPDATA%/KotobaSUB`. Tests use isolated paths. Settings writes use a temporary file plus atomic replacement. Invalid/out-of-range geometry is clamped before use, and a missing monitor cannot strand the overlay offscreen. Current milestone uses virtual desktop bounds; exact per-monitor layout profiles remain Milestone 6 work.

## Implemented structured-lyrics pipeline
Media metadata events produce track identity plus position, duration, playback rate/state and an observation timestamp. A controller cancels the prior generation on changes. Providers output normalized segments with source identity, start/end time, timing granularity and optional supplied translation. Japanese analysis enriches the current line on a worker while original text renders immediately. Rendering only receives finished immutable models, and redraws on a new line or settings change.

`IMediaMetadataProvider`, `ILyricsProvider` and `ILyricsSource` now have concrete consumers. `IAudioSource` and `ITranscriptionProvider` now have concrete consumers in `AudioTranscriptionSession`; introduce any later provider interfaces only with their concrete integrations. Avoid empty implementations or adding speculative interfaces with no consumer. Audio source selection remains abstract enough for process loopback/microphone later. Network calls receive cancellation tokens, timeouts and track generation checks. Audio buffers are bounded, disposed on pause and never uploaded. Cache keys include data format and analyzer versions.

Source eligibility requires reliable timing and match confidence. Caption priority does not imply a caption source exists. Line timing must never be turned into word timing. Provider errors clear stale data and route to the next eligible source. Annotation errors keep original Japanese. Optional translation cannot block rendering. Diagnostic text belongs in tray/logs, not the overlay.

## Privacy and resource boundaries
Normal mode now sends title/artist/search aliases to LRCLIB and NetEase, and candidate IDs to NetEase for lyric fetches. Duration stays local. The M4 engine captures default-output audio only while explicitly running, keeps bounded samples in memory, and never uploads or records them. Model/dictionary setup discloses ordinary download request metadata. Local speech audio, dictionary queries and logs remain local. Cloud translation is disabled unless explicitly configured. No telemetry or automatic online romanization. Normal idle rendering has no polling timer; timed playback schedules only needed cue boundaries.

`SmtcMetadataProvider` subscribes to session, media, playback and timeline events and marshals them to the WPF dispatcher. `LyricsSession` owns async request cancellation/generation checks and exposes the selected timeline. `PlaybackController` owns the native adapter, resolver, offsets and a one-shot dispatcher timer scheduled at the next boundary. There is no permanent playback poll. Seek/pause/resume update the monotonic position anchor. A removed track clears the displayed frame and cancels its query. Public LyricsSession mutation is confined to the UI synchronization context.

`LrcParser` handles multiple leading tags, millisecond fractions, integer-second tags, offset metadata, sorting, duplicate tags and explicit blank clearing cues. Positive LRC offsets advance cues; positive user offsets advance display through playback-position adjustment. The last cue ends at known media duration or eight seconds after its start if duration is unavailable. A `SubtitleFrame` supplies optional previous/current/next lines without inventing word timestamps.

`LyricsResolver` checks successful local cache first, then LRCLIB and bounded NetEase fallback. Requests use a six-second timeout and two-megabyte response limit. Cache records expire after 30 days and retain source ID, original, translation and romanization separately. Candidate matching validates recording version, title, artist and duration before accepting synchronized content. `KanaRomanizer` only converts kana; unknown kanji remain unchanged and cannot be treated as inferred readings. Wrong Lyrics excludes the selected candidate for the current session and bypasses cache on retry. Rejections are currently session-local.
## Implemented offline learning
KotobaSUB.Japanese implements Core's IJapaneseTokenizer, IDictionaryProvider and ISubtitleAnnotator. IpaTokenizer preserves surface spans and whitespace, distinguishes lexical/surface readings and joins contiguous auxiliary endings to verbs/adjectives. Unknown kanji get no guessed reading. JmdictDictionary filters spelling, reading, sense and part-of-speech restrictions before selecting glosses from read-only SQLite.

JmdictImporter streams entries with external XML resolution disabled, verifies a temporary database before replacing the destination, and records source SHA256/schema/date/count. LearningRenderer lazily initializes analysis on a worker and rejects results after source changes, clearing or disposal. Settings changes retain completed tokens. JapaneseAnnotator bounds memory/disk caches with tokenizer/dictionary version keys and preserves new timing on reuse. Kana-only furigana is suppressed; romaji is optional. Missing JMdict leaves readings available and logs the unavailable meanings provider. MetadataReadings supplies lazy, bounded IPADIC-backed aliases to LyricsResolver, MetadataMatching and LyricsCache. Resolution runs on a worker, including cache validation and dictionary initialization. New aliases match only exact normalized Latin readings against kanji; different-kanji forms are never compared by reading. Unknown kanji yield no alias. Native queries stay first with the existing three-query bound and all identity/duration/version gates retained.

## Implemented local audio-transcription engine
`WasapiLoopbackAudioSource` owns the default shared-mode Windows output recorder. It converts signed 16/24/32-bit PCM or 32-bit float callbacks to normalized mono samples, preserves resampler state across callbacks, and emits 20 ms blocks at 16 kHz. A locked queue holds at most 32 blocks; overload drops the oldest block and increments a diagnostic count. Sample indices expose discontinuities so speech state resets rather than joining audio across a gap. Start, stop, device errors and disposal surface explicit health states.

`SpeechActivityGate` rejects silence and short noise, retains pre-roll, closes utterances after trailing silence, and caps windows at six seconds with 0.75-second overlap. `StableTranscript` rejects low-confidence/no-speech output and common music/subtitle hallucinations, confirms repeated non-final prefixes, removes overlap duplicates and resets at an utterance boundary. `AudioTranscriptionSession` consumes both contracts sequentially, so only one inference runs at a time and cancellation stops capture without persisting samples.

`WhisperTranscriber` lazily loads the checksum-pinned multilingual base model through Whisper.net's x64 CPU runtime, fixes the language to Japanese, disables cross-window context, logs aggregate latency/confidence only, and disposes the model after two idle minutes or session disposal. Missing or incompatible local model/runtime becomes an unavailable/faulted status. At the M4 checkpoint, automatic selection remained isolated to M5; the following section records the completed integration.
## Implemented automatic source routing
`SubtitleSourceRouter` receives explicit suspension, structured-timeline presence, current lyric frame, ASR health and monotonic time. A valid lyric timeline owns output even at intentional blank cues. Without a structured timeline, the router waits 750 ms before requesting ASR, retains a transcript for at most four seconds after receipt and clears it on suspension or capture failure. Current source kinds are structured lyrics, local ASR and empty; the ordering leaves a higher caption provider slot available without pretending one exists.

`PlaybackController` composes the real WASAPI and Whisper session. Start/stop transitions are serialized. Every eligibility change advances a generation, and transcript callbacks carry the generation that started their capture so a late prior result cannot enter a later ASR run. WPF updates remain on the dispatcher. Preview, pause, structured-lyrics arrival and shutdown stop capture and reset the fallback clock/transcript. Manual Retry also resets a faulted/unavailable local session. The model resolves first from `%LOCALAPPDATA%/KotobaSUB/models`, then from repository `.data/models` during development.

The audio consumer flushes voiced samples after 650 ms without a new capture block. This handles short streams that stop yielding loopback packets before a trailing-silence block arrives. The pending async read is awaited before iterator disposal so stop/shutdown remains clean. Stable transcript deltas accumulate until a final utterance marker; the following utterance replaces the prior line rather than concatenating unrelated speech.
## Explicit local model installation
`WhisperModelInstaller` is shared by the tray action and Core tests. It requests the pinned HTTPS model URL only after an explicit user click, reads with response headers first, rejects an advertised or streamed size beyond 160,000,000 bytes, hashes while streaming, and moves the `.download` file into place only after the expected SHA256 matches. Cancellation, HTTP failure and checksum failure delete only the temporary file. Existing valid models are reused without a network request. The normal application resolves `%LOCALAPPDATA%/KotobaSUB/models/ggml-base.bin` first; the ignored repository model remains a development fallback.
## Freeze and local word inspection
Freeze is a secondary tray/hotkey state. `PlaybackController` retains the last rendered annotated frame while suspending metadata updates, lyric timing and local ASR. The tray records the prior lock state, unlocks only for Study interaction, then restores that state when live subtitles resume. `OverlayWindow` exposes token hit testing only while unlocked Study mode is active; a user click opens a small local detail window with the existing surface, reading, lemma, part of speech and JMdict glosses. No word request, account, browser or network call is introduced.
## Current-user startup

The tray's **Start with Windows** control uses `StartupRegistration` to create or remove only `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\KotobaSUB`. The value is the exact quoted published executable path and is unavailable to development `dotnet` launches, preventing an unusable `dotnet` Run command. No machine-wide key or elevation is used.

## Monitor-aware placement

Overlay settings now retain the active display device name plus normalized working-area coordinates whenever geometry is saved. On launch, `OverlayWindow` restores the normalized location when that device remains available. If it has been disconnected, the window resolves to the primary display and clamps the existing coordinates to that display's working area. Existing settings without monitor fields remain valid and are upgraded on the next geometry save.

## Lyric verification and learned alignment

The existing lyrics path remains provider-first: `LyricsResolver` applies metadata hard gates, `LyricsSession` owns the selected `LyricTimeline`, and `PlaybackController` composes structured lyrics with local ASR fallback. The verification extension retains a bounded shortlist of accepted LRCLIB/NetEase candidates, then evaluates actual ASR fragments as evidence without replacing provider text.

`LyricVerifier` is a Core component. It normalizes Japanese comparison copies, compares ASR fragments against nearby candidate lines, emits compact evidence anchors and maintains explicit confidence states. A separate `LyricAlignmentModel` projects provider timestamps through a robust automatic offset/drift estimate before the existing manual `SongOffsets` correction. Provider timestamps are never mutated.

Verification callbacks carry track identity, candidate key and generation. Playback cancellation, song changes, pause/freeze and retries invalidate stale work before persistence or rendering. `LyricVerificationStore` persists only bounded versioned assessments, compact anchors and learned alignment under local storage; raw audio and raw transcript windows are never written. See `LYRIC_VERIFICATION.md` for thresholds, state transitions, persistence and staged integration.
